## 1. CPU 启动流程

### 1.1 上电到第一条指令

```
电源接通
  │
  ▼
CPU 内部复位电路激活
  │
  ├─ 寄存器初始状态：
  │   EAX = 0
  │   EDX = CPU 标识（型号、步进等）
  │   CR0 = 0x60000010（PE=0, PG=0, 实模式）
  │   EFLAGS = 0x00000002
  │   CS = 0xF000
  │   IP = 0xFFF0
  │   其他寄存器 = 不确定
  │
  ├─ 第一条指令地址：
  │   物理地址 = CS*16 + IP = 0xF0000 + 0xFFF0 = 0xFFFF0
  │
  ▼
执行 BIOS ROM 中的第一条指令
  │
  ▼
BIOS POST (Power-On Self Test)
  │
  ├─ 检测关键硬件：CPU、内存、显卡、键盘
  ├─ 初始化芯片组和基本 I/O
  ├─ 构建中断向量表 (IVT) 在 0x00000-0x003FF
  ├─ 构建 BIOS 数据区 (BDA) 在 0x00400-0x004FF
  ├─ 扫描扩展 ROM (显卡 BIOS、网卡启动 ROM)
  │
  ├─ 按 CMOS 引导顺序扫描可启动设备：
  │   1. 软盘 (Drive 0x00)
  │   2. 硬盘 (Drive 0x80)
  │   3. CD-ROM
  │   4. 网络 (PXE)
  │
  ├─ 检查引导扇区的魔法数字：偏移 510-511 = 0xAA55
  │
  ▼
跳转到引导扇区执行地址 0x0000:0x7C00
```

### 1.2 BIOS 中断服务

在实模式下可用的关键 BIOS 中断：

```
INT 0x10 - 视频服务
  AH=0x00 设置视频模式 (AL=模式号)
  AH=0x0E 电传输出 (teletype output)
  AH=0x13 写字符串

INT 0x13 - 磁盘服务
  AH=0x00 复位磁盘系统
  AH=0x02 读扇区
  AH=0x03 写扇区
  AH=0x08 获取驱动器参数

INT 0x15 - 系统服务
  AH=0x88 获取扩展内存大小
  AH=0xE801 获取内存大小 (E820 的简易版)
  AH=0xE820 获取内存映射 (现代 BIOS)

INT 0x16 - 键盘服务
  AH=0x00 读取按键
  AH=0x01 检查按键状态

INT 0x19 - 重新引导 (reboot)
```

### 1.3 A20 地址线

**问题的历史根源：**

8086 有 20 条地址线（A0-A19），可寻址 1MB（0x00000-0xFFFFF）。当地址超过 0xFFFFF 时，由于只有 20 位地址总线，高位数会丢失（回绕）。

例如，`0xFFFF:0x0010` 的物理地址 = `0xFFFF0 + 0x0010 = 0x100000`，但 8086 只有 20 位，所以 `0x100000` 变成了 `0x00000`。

80286+ 有 24 条地址线可寻址 16MB，但为了兼容 8086 的"回绕"行为，IBM 在 AT 机上加入了一个逻辑门（"A20 门"）来控制 A20 地址线。

**A20 门控制：**

```
A20 = 0: 兼容 8086 (地址回绕，只能访问奇数 MB)
A20 = 1: 80286+ 正常模式 (可访问 1MB 以上的内存)
```

BIOS 通常已将 A20 打开，但为了安全，内核会显式启用：

```as
inb $0x92, %al        # 从系统控制端口 A 读取
orb $0x02, %al        # 设置 A20 位 (bit 1)
outb %al, $0x92       # 写回
```

其他启用方法还有键盘控制器法（out 0xD1/0xDF to 0x64/0x60）和 BIOS 法（int 0x15 AX=0x2401）。

### 2.3 分页硬件工作原理

**虚拟地址 → 物理地址的详细步骤：**

```
1. CPU 发出虚拟地址 VA（32位）

2. 硬件提取页目录索引 (VA[31:22])
   ￬
3. 从 CR3 读页目录物理地址
   ￬
4. 用 PDE_INDEX * 4 作为偏移，读取 PDE（4 字节）
   ├─ 如果 PDE.P == 0 → 页错误 (#PF)
   ￬
5. 硬件提取页表索引 (VA[21:12])
   ￬
6. 从 PDE[31:12] 读页表物理地址
   ￬
7. 用 PTE_INDEX * 4 作为偏移，读取 PTE（4 字节）
   ├─ 如果 PTE.P == 0 → 页错误 (#PF)
   ├─ 如果 PTE.R/W == 0 且有写操作 → 页错误 (#PF)
   ├─ 如果 PTE.U/S == 0 且 CPL==3 → 页错误 (#PF)
   ￬
8. 物理地址 = PTE[31:12] << 12 | VA[11:0] (页内偏移)
```

**TLB (Translation Lookaside Buffer)：**

TLB 是 MMU 内部的高速缓存，缓存最近使用的虚拟地址→物理地址映射。

```
TLB 刷新条件：
- 修改 CR3（重新加载页目录）：刷新整个 TLB
- INVLPG [addr]：只刷新一个地址的 TLB 条目
- 任务切换（修改 TR）：刷新整个 TLB
```

本项目使用 `write_cr3(read_cr3())` 技巧刷新整个 TLB：

```c
#define write_cr3(val) __asm__("movl %0, %%cr3" : : "r"(val))
#define read_cr3() ({ unsigned long __cr3; \
    __asm__("movl %%cr3, %0" : "=r"(__cr3)); __cr3; })

// 刷新 TLB
write_cr3(read_cr3());  // 原地重写 CR3
```

## 3. 中断系统

### 3.1 中断类型汇总

```
中断源              类型         向量         触发方式
───────────────────────────────────────────────────
除法错误            异常        0x00         CPU 内部
调试异常            异常        0x01         CPU
NMI                  硬中断      0x02         外部 NMI 引脚
断点                异常        0x03         INT 3 指令
溢出                异常        0x04         INTO 指令
越界                异常        0x05         BOUND 指令
操作码无效          异常        0x06         CPU
设备不可用          异常        0x07         CPU (无 FPU)
双重错误            异常        0x08         CPU
无效 TSS            异常        0x0A         CPU (任务切换时)
段不存在            异常        0x0B         CPU
栈段错误            异常        0x0C         CPU
一般保护错误        异常        0x0D         CPU
页错误              异常        0x0E         CPU
FPU 错误            异常        0x10         CPU
───────────────────────────────────────────────────
时钟中断 (PIT)      硬中断      0x20         8259A IRQ0
键盘中断            硬中断      0x21         8259A IRQ1
硬盘中断 (IDE)      硬中断      0x2E         8259A IRQ14
系统调用            软中断      0x80         INT 0x80 指令
```

### 3.2 8259A PIC 内部结构

```
IRQ0 ────→ ┌────────────┐
IRQ1 ────→ │            │
IRQ2 ────→ │  主 PIC    ├──→ INTR ──→ CPU
...        │  0x20/21  │
IRQ7 ────→ │            │
           └───┬────────┘
               │ IRQ2 级联
               ▼
IRQ8 ────→ ┌────────────┐
IRQ9 ────→ │            │
...        │  从 PIC    │
IRQ15 ───→ │  0xA0/A1  │
           └────────────┘
```

**PIC 寄存器：**

| 端口 | 寄存器 | 功能 |
|------|--------|------|
| 0x20 | 主 PIC 命令 (ICW1/OCW2/OCW3) | 初始化/EOI |
| 0x21 | 主 PIC 数据 (ICW2-4/OCW1) | 向量基址/掩码 |
| 0xA0 | 从 PIC 命令 | 同上 |
| 0xA1 | 从 PIC 数据 | 同上 |

**中断优先级：**
IRQ0 最高，IRQ7 最低。从 PIC 的中断都通过 IRQ2，所以 IRQ8-15 的优先级介于 IRQ1 和 IRQ3 之间。

**EOI (End of Interrupt) 时序：**

```
1. 中断发生 → CPU 响应 → 自动发送 INTA 给 PIC
2. PIC 发送中断向量给 CPU
3. CPU 保存现场，转 IDT 处理
4. 处理程序运行 (C 代码)
5. 处理程序向 PIC 发送 EOI: outb(0x20, 0x20)
   └ 如果来自 IRQ8-15，还需要: outb(0xA0, 0x20)
6. 执行 IRET，返回被中断的代码
```

## 4. I/O 系统

### 4.1 端口 I/O 地址空间

x86 有两个独立的地址空间：

```
内存地址空间:           I/O 地址空间:
0x00000000 ┌─────┐    0x0000 ┌─────┐
          │ RAM  │          │ DMA  │
          │      │    0x0020 │ PIC  │
          │      │    0x0040 │ PIT  │
          │      │    0x0060 │ KBC  │
0x000B8000│ VGA  │    0x0070 │ RTC  │
          │ RAM  │    0x0080 │ DMA  │
          │      │    0x00A0 │ PIC  │
0xFFFFFFFF└─────┘    0x00F0 │ FPU  │
                   0x01F0 │ IDE  │
                   0x03D4 │ VGA  │
                   0xFFFF └─────┘
```

**内存地址 vs I/O 地址的关键区别：**
- 内存地址：用 MOV 指令访问，经过 MMU 分页转换
- I/O 地址：用 IN/OUT 指令访问，不经过 MMU（直接访问硬件）
- I/O 地址空间只有 64KB（0x0000-0xFFFF）

### 4.2 时序与等待状态

I/O 操作比内存访问慢得多，旧的 ISA 总线设备（如 PIC、PIT）需要等待状态：

```as
outb %al, $0x20       # 写入 PIC
.word 0x00eb, 0x00eb  # JMP +2 (等待两个总线周期)
                      # 这确保 PIC 有足够时间处理命令
```

PCI 时代的设备通过可编程等待状态或状态轮询来解决时序问题。

## 5. 存储器映射 I/O (MMIO)

虽然 x86 主要使用 I/O 地址空间，但某些设备也通过内存映射访问：

### 5.1 VGA 文本模式缓冲区

```
物理地址: 0xB8000 - 0xB8FA0 (80×25×2 = 4000 字节)

每个字符占 2 字节（小端序）:
┌──────────┬──────────┐
│ 字节 0    │ 字节 1    │
│ 字符码    │ 属性字节  │
│ (ASCII)  │ (颜色等)  │
└──────────┴──────────┘

属性字节格式:
Bit 7      Bit 6-4    Bit 3      Bit 2-0
闪烁(1位)  背景色(3位) 高亮(1位)  前景色(3位)

颜色代码:
0=黑  1=蓝  2=绿  3=青
4=红  5=品红 6=棕 7=灰白
```

### 5.2 页目录和页表

页目录（0x100000-0x100FFF）和页表（0x101000-0x104FFF）也是通过内存映射的 MMIO——CPU 读取这些物理地址来执行地址转换。

## 7. 时钟与定时器

### 7.1 PIT (8253/8254 可编程间隔定时器)

```
8254 芯片有 3 个独立定时器通道：
────────────────────────────────────────────
通道 0: 系统时钟中断 (IRQ0, 端口 0x40)
通道 1: DRAM 刷新 (已废弃, 端口 0x41)
通道 2: PC 扬声器 (端口 0x42)
────────────────────────────────────────────

命令寄存器: 端口 0x43
模式/命令格式 (8位):
  Bit 7-6: 选择通道 (00=ch0, 01=ch1, 10=ch2)
  Bit 5-4: 读写方式 (11=先低字节后高字节)
  Bit 3-1: 工作模式 (011=方波发生器)
  Bit 0:   计数格式 (0=二进制, 1=BCD)
```

**频率计算：**

```
PIT 输入频率: 1.193182 MHz (从 14.31818 MHz 晶振 12 分频)
计数值 N = 1,193,182 / 期望频率

例：期望 100 Hz
  N = 1,193,182 / 100 ≈ 11931 (0x2E9B)
  写入: outb(0x9B, 0x40); outb(0x2E, 0x40)
```

### 7.2 jiffies 时钟滴答

```c
int jiffies = 0;     // 全局时钟滴答计数 (100Hz = 每 10ms 一次)
#define HZ 100       // 时钟频率

// jiffies 的用途：
// 1. 时间片管理: current->counter 以 jiffies 为单位
// 2. 系统时间: sys_time() 返回 jiffies / HZ
// 3. 调度触发: jiffies 每次中断递增，counter 递减到 0 时调度
```

## 8. DMA 与 PIO

### 8.1 PIO (Programmed I/O)

本项目的 IDE 硬盘驱动使用 PIO 模式：

```
PIO 数据传输流程 (读取):
1. CPU 向 IDE 控制器写入命令
2. CPU 轮询 IDE 状态寄存器等待 BSY=0, DRQ=1
3. CPU 执行 REP INSW 将数据从 IDE 数据端口读到内存
4. 每读一个扇区(256字)后重新轮询状态
```

**PIO 模式的问题：**
- CPU 参与每个数据字的传输
- 数据传输期间 CPU 无法执行其他任务
- 适用于数据量小、实时性要求不高的场景

### 8.2 DMA (Direct Memory Access)

DMA 允许设备直接访问内存，不需要 CPU 参与每个字节的传输：

```
DMA 数据传输流程:
1. CPU 设置 DMA 控制器：源地址、目标地址、传输大小
2. CPU 向设备发送命令
3. 设备向 DMA 控制器发送传输请求
4. DMA 控制器获得总线控制权
5. DMA 控制器在设备和内存之间传输数据
6. 传输完成后 DMA 控制器中断 CPU
```

本项目未使用 DMA，全部采用 PIO 模式。

## 9. 实模式内存布局

### 9.1 实模式寻址

```
物理地址 = 段寄存器 × 16 + 偏移

例：
  CS=0xF000, IP=0xFFF0 → 物理地址=0xFFFF0
  DS=0x0040, BX=0x0017 → 物理地址=0x00417
  SS=0x9000, SP=0xFF00 → 栈顶=0x9FF00
```

**段:偏移的多种等价表示：**

```
同一个物理地址 0x90200 可以表示为：
  0x9020:0x0000
  0x9000:0x0200
  0x0000:0x90200 (不可表示，越界)
```

### 9.2 实模式内存映射

```
0x00000-0x003FF: 中断向量表 (IVT), 256 个入口 × 4 字节
0x00400-0x004FF: BIOS 数据区 (BDA)
0x00500-0x07BFF: 常规内存（可用）
0x07C00-0x07DFF: 引导扇区 (512 字节)
0x07E00-0x9FBFF: 常规内存（可用）
0x9FC00-0x9FFFF: 扩展 BIOS 数据区 (EBDA), 1KB
0xA0000-0xBFFFF: 视频内存 (128KB)
0xC0000-0xC7FFF: 视频 BIOS (32KB)
0xC8000-0xEFFFF: 扩展 ROM / 可用
0xF0000-0xFFFFF: 系统 BIOS (64KB)
```

## 10. 保护模式内存管理单元

### 10.1 段描述符缓存

CPU 有隐藏的段描述符缓存寄存器。加载段选择子时，CPU 将描述符内容加载到这个高速缓存中，后续的段访问只需要查询缓存。

```
加载段寄存器时的操作：
  MOV DS, AX
  → 从 GDT/LDT 读取描述符
  → 加载到 DS 的隐藏描述符缓存
  → 后续使用 DS 的访存直接使用缓存，不查 GDT
```

### 10.2 权限检查流程

```
段级保护（在分页之前）:
1. 比较段的 DPL 和访问者的 CPL/RPL
2. CPL ≤ DPL (数值小=特权级高)
   │                     │
   成功，生成线性地址      失败 → #GP 异常

页级保护（在段之后）:
1. 检查 PDE 的 U/S 位 (0=supervisor only)
2. 检查 PTE 的 R/W 位 (0=read only)
3. CPL=3 访问 U/S=0 的页 → #PF
4. CPL=3 写 R/W=0 的页 → #PF
```

**保护优先级：段保护 > 页保护。** 段通过了，才检查分页。

### 10.3 任务切换硬件流程

```
LJMP TSS_SELECTOR (硬件任务切换):
1. 从 TR 获取当前 TSS
2. 将当前 CPU 状态保存到当前 TSS:
   - 所有通用寄存器 (EAX, ECX, EDX, EBX, ESP, EBP, ESI, EDI)
   - 所有段寄存器 (CS, DS, SS, ES, FS, GS)
   - EIP, EFLAGS, CR3, LDTR
3. 从新 TSS 加载 CPU 状态:
   - 同上，反方向
4. 设置 TR = 新 TSS 选择子
5. 设置 EFLAGS.NT = 1 (嵌套任务标志)
6. 从新 TSS 的 EIP 继续执行
```

**任务切换的开销：** 保存/恢复约 104 字节的 TSS + 潜在的 TLB 全部刷新 + cache 污染。
