# §10 内存管理 — `mm/memory.c` · `mm/page.s`

> 常量：`include/linux/mm.h`（`LOW_MEM=0x100000`、`PAGE_SIZE=4096`、`USED=100`、
> PTE 标志 `PTE_PRESENT/RW/USER/COW`）；地址全部来自 `include/memlayout.h`。
>
> **M3 起这一章讲的是「每进程独立地址空间」**：内核恒等映射 0–16MB（PDE[0..3]，共享、
> supervisor-only），每个进程另有自己的一份页目录，用户区只占 **PDE[32]**
> （虚拟 `0x08000000`–`0x08400000`）。用户页按需分配、fork 用写时复制。
> 旧的「单页表恒等映射 0–4MB + 固定用户物理地址 + `grant_user_pages` 授权」实现
> 已在 M3 删除，只在每节末尾的「M3 前」框里对照。

## 1. 两个地址空间

```
PDE[0..3]  0x00000000-0x01000000  内核恒等映射（物理==线性），supervisor-only
PDE[32]    0x08000000-0x08400000  当前进程的用户窗口，PTE=0x07
```

- **内核**为什么还要恒等映射：任务页、页表页、缓冲区缓存、`mem_map` 都在物理内存里，
  内核随时要用普通指针访问它们——不管 CR3 指向哪个进程。所以每份页目录的
  `PDE[0..3]` 都填同一批内核页表（`KERNEL_PT_COUNT=4`，boot/head.s 建立）。
- **用户**窗口为什么正好一个 PDE：一个进程只需要**一张额外页表**，开销固定 2 页
  （页目录 + 用户页表）；同时区域检查退化成简单的范围判断。

## 2. 全局与地址换算

```c
unsigned long memory_end;      // 可用 RAM 顶端（≤ KERNEL_IDENTITY_TOP = 16MB）
unsigned long *mem_map;        // 位图/引用计数数组，放在 RAM 末尾几 KB
int max_map_nr;
unsigned long kernel_pg_dir;   // = PAGE_DIRECTORY，内核任务的页目录
```

`MAP_NR(addr) = (addr - LOW_MEM) / PAGE_SIZE`，所以 **mem_map[0] 对应 1MB**，
1MB 以下（BIOS/内核映像/VGA）根本不进这张表。

`mem_map[i]` 的语义是**引用计数**：`0` 空闲；`1..USED-1` 被这么多地址空间使用
（写时复制就是靠它）；`USED(100)` 永久保留。

## 3. `mem_init(start_mem, end_mem)`

1. `max_map_nr = (end_mem - LOW_MEM) / PAGE_SIZE`，`mem_map` 放在 `end_mem - map_size`
2. 全表清 0
3. **保留页目录与前 4 张内核页表**（`[PAGE_DIRECTORY, KERNEL_TABLES_END)` = 5 页）
4. 保留 `mem_map` 自身占用的页
5. 其余全部空闲 —— 任务页、管道页和**所有用户页**都从这里来

缓冲区缓存的页不在这一步：`buffer_init()` 自己把 `[cache_start, BUFFER_CACHE_TOP)` 标 USED。
`main` 传入 `start_mem = &_end + 0x1000`、`end_mem` 由 INT 15h 得到并被夹到 16MB。

## 4. `get_free_page` / `free_page`

```c
unsigned long get_free_page(void);   // 首个空闲页，清零后返回；耗尽返回 0
void free_page(unsigned long addr);  // 引用计数 -1（USED 页拒绝）
```

**没有硬上限了**。旧实现用 `KERNEL_POOL_END` 把池拦在用户程序镜像之前，越过就 panic；
M3 之后用户页本来就是池里的普通页，所以"没内存"是正常情况：`fork` 返回 -1，
缺页处理打印 OOM 并只杀肇事进程（回归场景 18 专门验证这一点）。

## 5. 每进程地址空间

```c
unsigned long alloc_user_pgdir(void);          // 页目录 + 一张用户页表
void          free_user_space(unsigned long pgdir);
unsigned long alloc_user_page(unsigned long pgdir, unsigned long va);   // 建页+清零
void          map_user_page(unsigned long pgdir, unsigned long va, unsigned long pa, unsigned long flags);
int           free_page_tables(unsigned long pgdir, unsigned long from, unsigned long size);
int           user_addr_ok(unsigned long addr, unsigned long len);
```

`alloc_user_pgdir()` 填 `PDE[0..3] = 内核页表 | 0x03`、`PDE[32] = 新页表 | 0x07`，
其余为 0（所以用户窗口里没建过的地址就是 not-present，正好留给按需调页）。

`user_addr_ok()` 是"哪些地址算合法用户地址"的唯一判据：

| 区域 | 范围 | 用途 |
|------|------|------|
| 程序镜像 | `[0x08000000, 0x08100000)` | ELF LOAD 段 + BSS |
| 堆 | `[0x08100000, 0x08200000)` | `malloc` |
| **保护空洞** | `[0x08200000, 0x08300000)` | 访问 = SIGSEGV |
| 栈 | `[0x08300000, 0x083FF000)` | 向下按需增长 |
| 尾页 | `[0x083FF000, 0x08400000)` | argc/argv/sigreturn stub |

## 6. 写时复制（fork）

```c
int copy_page_tables(unsigned long from_pgdir, unsigned long to_pgdir);
static int un_wp_page(unsigned long address);
```

`copy_page_tables()` 遍历父页表：每个 present 页 `mem_map[]++`，并把**父子两侧的 PTE
都清掉 R/W、置上软件 COW 位（0x200）**——于是父子共享同一物理页但谁也写不进去。
`un_wp_page()` 在写缺页时被调用：分配新页、`memcpy` 4KB、把 PTE 换成新页并恢复可写、
`free_page()` 释放旧共享页（计数减一）。

> 位 9（0x200）被 386 忽略，这正是 Linux 0.01 当年拿它当 COW 标记的原因。

## 7. `page.s` + `do_no_page`

```as
page_fault:
  push ds/es/fs/gs ; pushal
  mov %cr2, %eax  →  address  (arg3)
  mov 0x38(%esp)  →  eip      (arg2)   # 注意：两次 push 之后错误码在 0x38
  mov 0x38(%esp)  →  error_code (arg1)
  call do_no_page
  ...
  add $4, %esp    # ★ 丢弃 CPU 压入的错误码，否则 iret 会整体错位一个字
  iret
```

两个**只有在按需调页落地后才会暴露**的坑（M3 修）：

1. 处理函数原先从不丢弃错误码。以前 `do_no_page` 一律杀进程、从不返回，所以 iret 少弹
   一个字也看不出来；改成会返回之后，iret 会把错误码当 eip，接着 #GP 死循环。
2. 读错误码的偏移曾写成 `0x34`，实际把 **eip** 当成错误码传了进去。

`do_no_page(error_code, eip, address)` 三个分支：

| 条件 | 动作 |
|------|------|
| present + 写 + PTE 带 COW | `un_wp_page()` 复制一份，返回后 CPU 重试那条写指令 |
| not present + `user_addr_ok()` | 分配一帧 → **先从可执行文件填入**（若是镜像页）→ 再建映射，返回后重试（**按需调页 + 文件回读**） |
| 其它（越权 / 空洞 / 无内存） | 打印 `PAGE FAULT`，`sys_exit(128+SIGSEGV)` 只杀肇事进程 |

第一条对 Ring0 同样成立：`sys_read` 往用户缓冲区拷贝时若撞上 COW 页，缺页同样被修好、
指令重试，内核代码不需要特殊处理。

**注意顺序**：帧是"先填后映射"的。若先建映射再填内容（第一版就是这样），填充期间
（从磁盘读会睡眠）这页在回收器眼里就是"全零的只读正文页"，可能被别的进程抢走复用。

## 7b. 页回收与文件后备（B3）

按需调页只解决"什么时候给页"；池子空了怎么办是另一半。`get_free_page()` 在扫描不到
空闲页时会调用 `try_to_free_page()`，按**代价从低到高**挑victim：

| 顺序 | 类型 | 丢弃的代价 | 说明 |
|------|------|-----------|------|
| 1 | 全零页 | 一次 memset | 新长出来的 .bss/堆大多是这种，重建就是重新给一页零页 |
| 2 | 只读镜像页（正文） | 一次磁盘读 | `execve` 记了 `exe_regions[]` + `exe_inode`，`page_in_image()` 用 `file_read()` 读回 |
| 3 | COW 共享页 | **不产生空闲帧**（帧留给另一个 owner） | 只作兜底，仅解除本进程映射；因为不还帧，`get_free_page()` 会重试若干次 |
| — | 私有脏页（堆/栈） | 无后备存储（本内核没有交换区） | **永不回收** |

扫描的是**所有进程**的用户页表（申请不到页的进程往往不是持有可回收页的那个），并用游标
轮转。零页优先不只是省事：第一版按地址顺序扫，总是先撞到窗口底部的正文页，于是每次缺页
都丢掉正文、下一次缺页又去读磁盘——4MB 机器上的回收测试全耗在等硬盘上。

**观测**：`memstat` 打印 `page faults / demand pages / COW breaks / out-of-memory`、
`image pages read back from the executable`、`disk interrupts`、`pages evicted / COW mappings
dropped`；前 10 次回收还会打印一行 `evict: zero|text page 0x... from pid=N`。

**信号投递的一个后果**（写压力测试时踩到）：本内核只在**系统调用返回**时投递信号，
所以一个埋在"纯内存写"缺页循环里的进程，`kill`/`alarm` 都要等它下次进内核才生效。
`user/evicttest.c` 因此在循环里定期做一次 `times()`。

## 8. 与 buffer / malloc 的边界

| 分配器 | 位置 | 释放 |
|--------|------|------|
| 页帧 `get_free_page` | mem_map 里的空闲页（含全部用户页）；池空时先尝试回收 | `free_page`（引用计数） |
| buffer 缓存 | `BUFFER_CACHE_TOP` 向下，`buffer_init` 标 USED | 不还回页分配器 |
| 用户堆 | `user/lib.c` bump+freelist（`0x08100000`–`0x08200000`），页按需由内核提供 | `free` |
| `lib/malloc` | bump from `KERNEL_HEAP_START`(0x30000) 到 `KERNEL_HEAP_END`(0x40000) | 无 free |

## 9. 观测：`memstat`

内核 shell 的 `memstat` 打印空闲页数、当前任务映射页数，以及缺页/按需建页/COW/ OOM 计数
（`nr_page_faults`、`nr_demand_pages`、`nr_cow_breaks`、`nr_oom`）。跑一次 `demandtest`
或 `cowtest` 前后各看一次，能直接看到这些数字怎么涨。
